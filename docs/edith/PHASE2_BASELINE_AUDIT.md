# Phase 2 baseline audit

Verified on 2026-11-13 before Phase 2 application edits. The Phase 1 working tree is uncommitted and is preserved. Baseline: 34 unit tests (33 pass, one privilege-dependent file-symlink skip), plus security, file, voice, browser and configuration integration checks passing. Output is retained locally in ignored data/phase2-baseline-tests.txt.

Actual stack: Node 20.11, Express 4, plain browser modules, ws, Gemini Live (@google/genai), Ajv, jsonc-parser and Fuse. Existing tools/FileIndex is an in-memory metadata map, recursive watcher and Fuse search; ResultStore issues session-scoped references; FileService and registry connect it to voice and UI. No SQLite dependency or worker exists at baseline.

Verified Phase 1 interfaces: safety/authority.mjs (current user principal), policy.mjs (branded permits), permissions.mjs (tool scopes), sessions.mjs (cookie/CSRF/Origin), audit.mjs (serialized redacted chain), cloudGate.mjs (local-only egress), config.mjs and pathRules.mjs (immutable protected rules), tools/pathGuard.mjs (canonical capabilities), windows.mjs (Notepad/reveal). server.mjs wires all of them into Gemini/HTTP and public/files.js renders the existing panel. No security prerequisite is missing.

Integration: replace the existing FileIndex internals behind the same service contract, retain PathGuard/registry/adapters, use one Node worker for database and crawling, extend the existing SSE and file panel. Keep allowed roots explicit, add discover-only fixed-volume reporting, and preserve local-only filtering. Introduce only the requested SQLite dependency, node-sqlite3-wasm 0.8.61 (SQLite 3.54.1 verified locally, FTS5 enabled), without native compilation or a Node upgrade. Its synchronous filesystem VFS is confined to the worker. Because it lacks general cross-process locking/WAL, enforce one application owner with an exclusive PID lock and use rollback-journal transactions, rather than claiming WAL. No second framework, provider, service or database server is needed.

Compatibility risks: existing tests assume immediate complete scans and in-memory entries. Adapt test observation to asynchronous worker APIs, while retaining start-and-wait for explicit test/service startup. Existing safe-open formats remain restricted; PDF/Office metadata discovery does not authorize arbitrary Windows associations. Existing Phase 1 documents describe the completed previous phase and are retained as historical records. New Phase 2 configuration is restart-based, with safe authenticated index controls and read-only settings in the UI; it cannot override protected paths.
